# Audit of the LMCS camera-ready (FINAL/) — 2026-09-05

How this was produced: I read all nine .tex files myself, cloned the public ChoreoPRISM repository, rendered the PDF pages with the definitions and the proof, fetched the PRISM manual (synchronisation, commands) and the Itai–Rodeh case-study page, and ran a 10-lens agent audit. The 10 finders and the dedup step completed (58 distinct findings). The adversarial verification (3 refuters per finding) completed for 17 of the 58 before the run died on quota; every one of those 51 votes was "not refuted". The remaining 41 findings are unverified by refuters; where I could, I checked them myself and say so below.

Bottom line: no false theorem was found. Nobody (me, the hostile-referee agent, the fresh-referee agent) could construct a counterexample to the one-step Projection Theorem under the intended reading of the definitions. What was found is (a) a definition that is literally ill-founded (strong connectedness of recursive choreographies), (b) a handful of genuine errors in examples, remarks and listings, (c) several definitions whose literal text does not say what the proof needs, and (d) overclaims in Section 6 that the repository and the figures contradict. All are fixable in hours, none needs a new proof.

Legend. [V] = triple-verified by refuters (textual, technical, materiality) with no refutation. [M] = checked by me directly. [A] = agent finding, plausible, not independently verified. Line numbers refer to FINAL/*.tex as of today.

## 1. Theory (Sections 3–5)

### 1.1 Must fix

**T1 [V] sConn(X) is not derivable for any recursive definition** — proj.tex:517–521.
The rules are an inference system; the paper elsewhere says such relations are "the smallest relation satisfying the rules". Under that reading sConn(X) needs sConn(C_X) which needs sConn(X): infinite derivation, never derivable. So the paper's own example on l.540–550 is not strongly connected, and the theorem's hypothesis is unsatisfiable for every recursive choreography in the paper (Ex. 2, Ex. 5.4, Rem. 2, all six benchmarks).
Fix (one sentence): "sConn is defined coinductively (as the largest relation closed under the rules)"; or, more standard, "sConn(X) holds by assumption while checking the body of X; a set of definitions is strongly connected if every body is".

**T2 [V] Precedence of the sConn premises** — proj.tex:500 and 513.
`∀j. sConn(C_j) ∧ hMods(C_j)≠∅ ⇒ ...` parses (∧ binds tighter than ⇒) as `(sConn(C_j) ∧ hMods≠∅) ⇒ ...`, which is vacuously true whenever C_j is not connected, i.e. sConn(C_j) is never required. Under that literal reading the hostile-referee agent built a "strongly connected" choreography whose projection has an extra enabled synchronisation at S_+ (theorem fails). Fix: parenthesise `sConn(C_j) ∧ (hMods(C_j)≠∅ ⇒ ...)`.

**T3 [V] "non-contractive" is backwards** — chor.tex:55–57.
`X def= X` is the paradigmatic non-contractive (unguarded) definition; the assumption being made is that definitions are contractive/guarded. Also, as stated it does not exclude X def= Y, Y def= X, for which hMods(X) (proj.tex:485) never returns. Fix: "we assume definitions are contractive (guarded), i.e. every call occurs under an interaction or a conditional".

**T4 [V] Remark 2 displays the wrong rate** — proj.tex:803–804.
The d-synchronisation has rate 1·1 = 1 (both call commands carry 1), and λ is not bound in the remark. The line above correctly shows →_1. Also the source state was introduced as S_0^+, not S_+. Fix: `\red{1}`, `S_0^+`.

**T5 [M] Example 1 defines C′ with the wrong rate** — chor.tex:161.
`C' = p→{q} λ_1:(x'=1); 0` should be λ_2 (the figure's second edge is λ_2).

**T6 [V] Rule (Transition) does not say what it sums over** — prism.tex:107–115.
Premise "∀j,α. M ⇝ F_j, S ⊢ F_j" leaves the family {F_j} free (any sub-family, even empty, satisfies it) and α occurs nowhere else. Fix: "where {F_j}_j is the set of all commands F with M ⇝ F and S ⊢ F" (that is what the prose l.100–105 intends).

**T7 [V] Proof: "by induction on C" is a case analysis; misattributed rule; wrong subscript** — proj.tex:590, 633–635, 605–610.
No case uses an induction hypothesis. l.633 says the only-if direction "follows by applying rule (Interact), whose premise is satisfied by deriving via (P2)"; (Interact) has no premise — the rule whose premises are discharged is (Transition). l.605: "Module p is projected as" but the displayed guard is `s_q = ι` (copied from the definition where q is the generic module); same for the p_i display. Fix: "by case analysis on the shape of C^a"; "rule (Transition)"; rename q→p / q→p_i in the two displays.

**T8 [V] The key step of the converse direction is asserted, and one justification is wrong** — proj.tex:627–631, 657–671, 691–695.
l.627–631 "any other command among these modules must be enabled by a different state label" is false as stated: a non-participant keeps its label across branches (the paper says so at l.113–116), so a command of an untaken branch, or the barrier command of a call in a sibling branch, can be guarded by exactly the label the module currently has. Such a command is blocked only because all its synchronisation partners must also match and at least one participant's label differs. The (Transition) rate is a sum over all enabled commands to the same S′_+, so one must also say that no other enabled command reaches the same S′_+ (true, distinct successor labels). Suggested fix: state the invariant once as a short lemma — "in every reachable S_+, for every module q, the commands of q enabled by s_q are those of syntactic points at which q has label S_+(s_q); a synchronised command fires only if all its participants are at the same syntactic point, which by freshness is the current one; conditionals are enabled only for the module that owns the label" — and cite it in each case. The "no causal dependency … standard [CHY12]" sentence is then unnecessary. This is what "complete proof" in the Changes paragraph (introduction.tex:158–160) commits you to.

**T9 [A, agreed by me] The theorem is one-step on a network recomputed at every step** — proj.tex:569–588.
The right-hand side is N(C^a) for the current C. It cannot be iterated: the hypothesis "C^a = annot(C,σ) for fresh σ" fails for the reductum, and N(C_1^a) ⊊ N(C^a) (Remark 2). So nothing is formally said about the second and later transitions of the model the user actually model-checks, N(C_0^a). Recommended fix (proof unchanged): state the theorem for the fixed network N(C_0^a) and any reachable (S,C^a) — "if (S_0,C_0^a) →* (S,C^a) and S_+(s_q)=top_q(C^a) then (S,C^a) →_λ (S′,C_1^a) iff N(C_0^a) ⊢ S_+ →_λ S′_+". The same invariant (T8) proves it, because the extra commands of N(C_0^a) are guarded by labels of untaken branches. If you prefer not to touch the statement, at least say explicitly that it is a one-step result and that Remark 2 explains why.

**T10 [V] top is not a function as written** — proj.tex:157–160, 167–169.
The generic-q clauses lack the side conditions q ∉ {p,p_1..p_n} (resp. q ≠ p), so for a participant two clauses apply. Also clause 3 uses C_1 (presupposes 1 ∈ J). Fix: add the side conditions. Optionally replace the "always defined" observation (l.180–183) by the provable and more useful fact top_q(annot(C,σ)) = σ(q) for all q.

**T11 [A, agreed by me] Freshness per branch is not expressed by Def. annot** — proj.tex:70–73, 85, 347–350.
"∀j∈J. annot(C_j, σ[p ↦ fresh_s, …])" and "∀i∈{1,2}. σ_i = σ[p ↦ fresh_s]" literally give every branch the same labels, and Ex. 5.4 writes "σ_1, σ_2 = σ[…]" which reads as σ_1 = σ_2. The proof relies on per-branch distinctness (l.627, 722). Fix: one sentence "each occurrence of fresh_s / fresh_c denotes a label distinct from all labels used so far, so different branches receive different labels", and write σ_1 ≠ σ_2 in the example.

**T12 [A, agreed by me] N(C^a) is not well-typed and the range of q is undefined** — proj.tex:318–324.
proj_D returns a set of commands; the network grammar of Sec. 4 needs `q:{F_i}` and only defines the binary `|[A]|`, not the alphabetised `||`. "q ∈ C^a" is undefined; read syntactically it is empty for C^a = X^{d,σ′} (Ex. 5.4, Rem. 2) and it omits modules occurring only in definition bodies. Fix: N(C^a) = ||_q q:{proj_D(q,C^a)} with q ranging over the modules of C^a and of D, and "|| is the alphabetised composition, i.e. |[A]| with A the shared labels".

**T13 [A, agreed by me] Def. projDTMC: "the other cases are equivalent" is not literally true** — proj.tex:459–460.
The partner clause of Def. 5.3 guards on ι_i, which under the DTMC pattern is the initiator's intermediate label; it must be restated with ι_i′. Also the ι_j are only "unique identifiers generated from ι", never said to be distinct from all annot labels. One sentence fixes both.

**T14 [V] Remark 5.9: "in every reachable state exactly one command is enabled" is false for the CTMC projection and for terminal states** — proj.tex:773–778.
At an interaction with |J| branches the CTMC projection enables |J| synchronised commands (the race); at 0^σ no command is enabled (deadlock, PRISM needs -fixdl). Restrict the sentence to the DTMC projection and to non-terminal states; the "no normalisation needed" conclusion survives. Also (l.769–771) the DTMC chains are not isomorphic — every interaction is one step in the choreography and two in the projection — so step-bounded properties differ; say "holds up to this two-step matching".

### 1.2 Should fix (imprecision a referee would flag)

**T15 [V] Example 3 is not "the" network of Example 2** — prism.tex:223–225, proj.tex:329–331, introduction.tex:80–108.
Its resets are unlabelled and independent: after a synchronisation the CTMC passes through (s_p,s_q) = (1,0) or (0,1) with two Exp(1) steps and there is no counterpart of the rate-1 (Call) step; Ex. 5.4's projection synchronises resets on b,c,d. "Can be described by" / "implement the same behaviour" → "a hand-written network with similar behaviour" (or label the resets).

**T16 [V] Relation-based semantics vs "unique distribution"** — chor.tex:96–130.
A set of tuples cannot record multiplicity: two branches with equal λ, u_j and C_j collapse (mass lost); two branches with different λ to the same (S′,C′) give two edges, never summed. Sec. 4 sums explicitly (μ, Transition); Sec. 3 does not. Fix: "the rate/probability of (S,C) → (S′,C′) is the sum of the labels of all rule instances with that conclusion" (annotated choreographies make branches distinct anyway). Also (S,0) has no distribution (absorbing convention) and D should define each X at most once.

**T17 [V] Prose interaction term ≠ grammar** — chor.tex:30–31: `Σ{λ_j : x_j=E_j . C_j}` vs `Σ_j λ_j : u_j ; C_j`.

**T18 [V] Prose description of sConn ≠ rules** — proj.tex:526–537. The rules only require the next action to share a participant with the current one; the prose demands that every other module's first action be with one of p_1..p_n and omits p.

**T19 [V] allsynch encoding** — chor.tex:398–429. (i) The `else if (x=5 & z≠3)` has no else, so the term is not in the grammar (and discussion.tex:77–79 says if-without-else is forbidden). (ii) Under the paper's semantics each conditional is a separate rate-1 step, so the encoding is not equivalent as a CTMC/DTMC (two Exp(1) delays before the race; expected time ≈ 2 + 1/119 vs 1/119); and it is not strongly connected (an if at q follows an if at p). Fix: add `else 0`; write "equivalent up to the rate-1 evaluation steps of conditionals" and drop "not introducing any new expressiveness".

**T20 [V] Parametric modules** — chor.tex:288–323. The sequential encoding `p1→q1; p2→q2; …` is a different Markov chain from n independent copies running in parallel, which is what PRISM renaming and the tool produce (all instances enabled at control state 0). "As done in PRISM" and "redundant" are unjustified; the indexed benchmarks are outside the formal semantics. Say so in one sentence (it is also the concurrency limitation you already state in Sec. 7).

**T21 [A] Minor definitional gaps**: variable ownership ("located at") is never defined but Assumption 3.1, u_j↓q and the PRISM fragment rely on it (chor.tex:62, prism.tex:71); "writable choreography" undefined; injectivity of σ is required but never used (proj.tex:46); the annotated conditional is written `a: if E@p^ι` in the syntax and `if E@^a p^ι` everywhere else, and its control label is never used (proj.tex:39); `[alpha_1,alpha_2]` multi-label commands are not PRISM syntax (example.tex:21,23); the reason given for needing Def. 5.5 (l.432–439) is not the actual obstacle — under your own (P2) all modules do take the same branch; the obstacle is that `[a_j] … → λ_j : …` with a single update violates "probabilities sum to 1" per command.

### 1.3 Verified as correct (do not touch)
All numbers in the DTMC example of Sec. 4 (products 0.2/0.2/0.3/0.3, sums 1.2/1.3/0.2/0.3, normalised 0.4/0.433/0.067/0.1); the six-state chain of Ex. 2; eq. ## 2. Examples and benchmarks (Sections 2 and 6)

**B1 [V] μ and θ swapped in the thinkteam choreography** — example.tex:58–60 and tests.tex:55–56.
PRISM: state 1 → 0 with μ (beta), state 2 → 1/2 with θ (gamma). Choreography: C1 (= state 1) carries θ, C2 carries μ. The generated User2 in Listing 2 (tests.tex:79–81) has 1→0 with mu and 2→1/2 with theta, i.e. it matches the original and cannot have been produced from the printed choreography. Fix: C1 uses `1*mu`, C2 uses `1*theta`, in both listings.

**B2 [V] Concrete rate syntax `["A*B"]` is never explained, and Sec. 2 puts the rate on the receiver** — example.tex:58, 86–98.
In the tool (BranchNode.java:145–146 and 285–286) A is the initiator's rate and B is emitted on every receiver. The paper never says so; Def. 5.3 puts λ_j on the initiator and 1 on receivers, while the Sec. 2 correspondence shows User (receiver) with lambda and CheckOut with 1. One sentence in Sec. 2 or 6: "in the concrete syntax a rate `A*B` places A on the initiator and B on each receiver; the synchronised rate is their product".

**B3 [V] Modified thinkteam: two receivers each get `lambda`, so the synchronised rate is λ² (μ², θ²)** — tests.tex:53–56, 77.
By your own (P2) and PRISM's product rule. The generated model is not the intended CTMC. Fix: write `["lambda*1"]`, `["mu*1"]`, `["theta*1"]` (rate on the initiator, as in Def. 5.3) and regenerate/adjust Listing 2 (CheckOut then carries the rates, User1/User2 carry 1).

**B4 [V] "For the first four benchmarks … exact model checking; for the two larger (Bitcoin, Casper) … simulation"** — tests.tex:41–45. Bitcoin and Casper are the 3rd and 4th in the list. Also no property or number is ever reported for the modified thinkteam although l.16–17 promises a comparison.

**B5 [V] "This implementation realises the projection formally defined in Section 5 … guarantees that the semantics … coincide"** — tests.tex:4–10.
The tool folds recursive calls into the preceding command (no call label, no rate-1 barrier — every generated listing and the repo show `(X'=0)` in the last update), puts rates on receivers, and merges conditionals into the following command; Def. 5.3 emits a global rate-1 synchronisation on a fresh label for every call. The formal projection of thinkteam would add an Exp(1) step per recursion and would not reproduce the original CTMC. Fix: "implements a variant of the projection of Section 5, in which recursive calls are folded into the preceding command and the rate of an interaction is split between initiator and receivers"; delete "guarantees".

**B6 [V] Self-interactions and local actions are outside the formal language** — tests.tex:89 (`Client[i] → Client[i]`), 305 (`crypt[i] → crypt[i]`), 137 (`["r"] u@Miner[i]`). chor.tex:30–32 requires all participants distinct; Sec. 3.3 lists no local action. \begin{cor}\label{cor:run}
```latex
Let $\anno C_0=\mathsf{annot}(C_0,\sigma_0)$ with $\sconnected(C_0)$, and let
$\mathcal M$ be the set of modules of the program. For every configuration
$(S,\anno C)$ reachable from $(S_0,\anno C_0)$ and every extension $S_+$ of $S$

  (S,\anno C)\red\lambda(S',\anno C_1)

  \mathcal N(\anno C_0)\vdash S_+\red\lambda S'_+ ,
\]
where $S'=S'_+\backslash\{s_\nrr\}_{\nrr\in\mathcal M}$ and
$S'_+(s_\nrr)=\topannotation\nrr{\anno C_1}$ for all $\nrr\in\mathcal M$.
\end{cor}
\begin{proof}
By induction on the reduction sequence, using Theorem~\ref{thm:epp} at each
step. Every reachable $\anno C$ is a subterm of $\anno C_0$ or of an annotated
definition body, hence $\proj(\nrr,\anno C)\subseteq\projD(\nrr,\anno C_0)$.

not taken has at least one participant whose state label was generated inside
that branch, and every command generated for an interaction carries a control
label shared by all its participants, so rule $(\mathsf{P_1})$ cannot fire it
in isolation and rule $(\mathsf{P_2})$ is blocked.
\end{proof}
```
